# kedalab の使い方

kedalab は「**この出力が出たら次は何をするか**」を引くための、ペネトレ／AI Red Teaming の個人ナレッジ集です。コマンド集ではなく**判断フロー**として使います。

---

## 基本の考え方

1. **Playbook（判断フロー）を上から進める** — 最初から技術ファイルを全部読まない
2. コマンドを打ち、出力を**判断表と照合**して次の手を選ぶ
3. 「このコマンド何？」となって**初めて**該当の技術ファイルを開く
4. 詰まったら各技術ファイルの「**刺さらなかったとき**」→「注意点・落とし穴」の順に見る

> 本番のペネトレではフローに入る前にスコープ・実施可否・業務影響を合意する。演習環境（HTB / OSCP 等）ではスキップしてよい。

---

## 上部タブの役割

| タブ | 何をする所か |
|---|---|
| **Start** | 「何が手元にあるか（IP だけ／ドメイン／認証情報 等）」から、開くべき Playbook を引く入口 |
| **Browser** | 技術名・CVE・タグ・本文で**フィルタ検索**。ピンポイントで技術を引く |
| **Workspace** | 実戦用の作業ページ（後述）。左 **Triage** ＋ 右 **Worksheet** を横並びで使う |
| **Navigator** | 技術を**前／後／関連**でつないだマトリックス。「この技術の前後に何をやるか」を辿る |
| **Raw** | 索引ファイル（TECHNIQUES_INDEX 等）の原文を直接開く |
| **使い方** | このページ |

検索はどの画面でも `Ctrl + K`（コマンドパレット）で呼べます。

---

## Workspace — 実戦の中心

左右 2 カラムで、**照合 → 記入**を往復します。**入力したファイル・メモはすべてブラウザ内だけで処理され、外部に送信されません**（ターゲット情報を扱う前提）。

### 左: Triage（照合）🚧 開発中・随時更新
`.req` / `.res` / `.txt`（nmap 出力やメモ）を**ドロップ or 貼り付け**して `照合する` →
本文から意味のあるシグナル（サービス版数・エラー文字列・パラメータ等）を拾い、
**次に見るべき kedalab ファイルを確証度順**で示唆します。`↗` でその場で本文が開きます。

### 右: Worksheet（型 / 作戦ノート）🚧 開発中・随時更新
HTB / OSCP / 本番で毎回埋める**チェックリスト兼作戦ノート**。フェーズ別の項目に kedalab への直リンクが付いています。

- チェックは**クリックで 3 状態**を循環： `·` 未着手 → `✓` 完了 → `–` 対象外（進捗カウントの分母から除外）
- 各セクション見出しの `✓全 / –外 / 解除` で**節ごと一括**設定
- 記入は**自動保存**（リロードしても残る）。`↓ .md` / `↓ .txt` で書き出し
- 終わったら書き出して保存 → 次のターゲットは `クリア（新規）`

---

## 典型的な 1 ホストの流れ

1. **Workspace** を開き、ターゲット情報を記入
2. nmap を回す → 出力を **Triage** に貼って `照合する` → 見るべきファイルを把握、Worksheet にチェック＋メモ
3. Web レスポンス等も Triage に貼って当たりを付ける
4. 詰まったら **Browser**（`Ctrl+K`）／**Navigator** で深掘り
5. 進むたびに Worksheet を埋める（foothold / loot / privesc / proof）
6. 終了時に `↓ .md` で書き出し → 記録・レポート素材に

---

> 🚧 Triage / Worksheet は開発中で、ルールや型は随時追加・改善しています。示唆は補助であり網羅性・正確性は保証しません。
