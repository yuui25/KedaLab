# ソーシャルエンジニアリング

> **スコープ**: 技術的な脆弱性ではなく人間の心理を操作して初期アクセスを取得する手法。フィッシング〜プリテキスティング〜ベイティングの各手法と、本番での法的・契約的前提を扱う。取得した認証情報の活用は `Credential_Discovery.md` を参照。

> **[HIGH IMPACT]** 本攻撃カテゴリは本番で実施する場合に特別な事前合意が必須：
> - [x] 業務停止リスク（対象従業員の業務遂行への影響）
> - [x] 法的リスク（個人情報保護法・労働法・不正アクセス禁止法）
> - [x] 第三者影響（家族・取引先への波及可能性）
> - [x] レピュテーションリスク（対象組織従業員間の信頼関係）
>
> 書面承認・対象者リスト・実施手段・通知範囲を明示的に取り決めない限り実施しないこと。演習環境（HTB / OSCP 等）では制約なし。

## 着火条件

- 標的組織の従業員・ユーザーへの連絡手段がある（メール・電話・SNS 等）
- 技術的な侵入経路がなく、または補完手段として人間を介したアクセス取得が有効な場合
- 標的の組織・業務・役割・利用ツールに関する情報が OSINT 等で入手できている

## 環境前提

- 実行環境: テスター端末（ペイロード作成・フィッシングページ設置）/ 対象従業員のデバイス（攻撃の発火場所）
- 必要なツール: Evilginx / GoPhish 等（フィッシングキット）。具体的なツール選定は実施目的・合意内容に応じて判断する
- 法的前提: **書面承認なしの実施は不正アクセス禁止法・個人情報保護法・脅迫罪等の犯罪となりうる**

## 先に確認すること

- **対象者リスト・実施手段・通知範囲の書面合意が取れているか**（本ファイルの「本番での前提」を先に読む）
- **OSINT フェーズの完了**: 組織構造・利用システム・担当者名を事前に把握しているか。情報の質がソーシャルエンジニアリングの成功率に直結する

**ソーシャルエンジニアリングのシグナルチェーン:**

```
OSINT で組織情報収集（従業員名・役職・利用ツール・メールアドレス形式）
    ↓
高価値標的を選定（IT 管理者・データアクセス権保持者・管理職等）
    ↓
フィッシング / プリテキスティング / ベイティング を実行
    ↓
[認証情報を取得]                [マルウェアを実行させる]
    ↓                               ↓
直接ログイン →                  C2 接続・バックドア確立 →
技術的な侵入フェーズへ移行       技術的な侵入フェーズへ移行
```

**攻撃者の思考トレース:** ソーシャルエンジニアリングは技術的なセキュリティ制御をバイパスする経路として機能する。MFA でもリアルタイム中間者攻撃（Evilginx 等）でバイパス可能なケースがある。複合攻撃（SE で認証情報取得→技術的手法で権限昇格）が主流で、SE 単独で攻撃が完結することは少ない。

## 1. フィッシング（Phishing）

信頼できる組織・個人を装ったメールや Web ページで認証情報・機密情報を詐取する手法。

**バリエーション:**

| バリエーション | 特徴 |
|------------|------|
| スピアフィッシング | 特定個人・組織を標的に高度にパーソナライズ |
| ホエーリング（Whaling）| 経営幹部・管理職など高権限者を標的 |
| スミッシング | SMS を使用 |
| ビッシング | 音声通話を使用 |
| BEC（ビジネスメール詐欺）| 上司・役員を装い緊急の送金指示・情報提供を要求 |

**認証情報フィッシングの流れ:**

1. 正規サービス（VPN・メール・社内ポータル）のログインページを模した偽サイトを準備
2. 標的に偽サイトへの誘導メールを送信（緊急性・権威を装う）
3. 入力された認証情報を攻撃者サーバーに送信・収集
4. 取得した認証情報で本物のシステムに直接アクセス

**観測される出力 → 次のアクション:**

| 出力 | 示唆 | 次のアクション |
|---|---|---|
| 認証情報が攻撃者サーバーに届く | フィッシング成功 | `Credential_Discovery.md`（パスワード使い回し確認）→ 技術的な侵入フェーズへ |
| 標的が通報する | SOC 内部調査が動く可能性 | 即時中断手順を実行（事前に SOC 担当者との連絡ラインを確立しておく）|
| MFA でブロックされる | 2FA が有効 | Evilginx 等のリアルタイム中間者攻撃（AITM）フィッシングキットを検討 |

**注意:** フィッシングの成否は事前情報の質に依存する。利用ツール・上司の名前・組織内のイベント等に合わせてパーソナライズするほど成功率が上がる。

## 2. プリテキスティング（Pretexting）

架空のシナリオを作り上げ、標的が「自発的に」情報・アクセス権を提供する状況を作り出す手法。

**典型シナリオ:**

| 典型シナリオ | 手口 |
|-----------|------|
| IT サポートを装う | 「システム障害対応のためパスワードの確認が必要です」 |
| 監査員・コンプライアンス担当を装う | 「セキュリティ監査のためアクセス権限の確認をお願いします」 |
| ベンダー・取引先を装う | 「システム更新のため VPN 接続情報の提供が必要です」 |
| 新入社員を装う | 「アカウントのセットアップで困っているため教えていただけますか」 |

**観測される出力 → 次のアクション:**

| 出力 | 示唆 | 次のアクション |
|---|---|---|
| 標的が自発的に認証情報・アクセス権を提供 | プリテキスティング成功 | 技術的な侵入フェーズへ移行 |
| 標的が確認・拒否する | 組織のセキュリティ意識が高い | 別のシナリオや標的に切り替える |

**注意（プリテキスティングの成立条件）:** 組織構造・利用システム・担当者名を事前に把握しているか。権威ある立場を装い（IT 管理者・外部監査・上司）、緊急性・締め切りを強調して標的の判断の余裕を奪う構造が有効。

---

## 3. ベイティング（Baiting）

悪意あるデバイス・ファイルを意図的に放置・配布し、標的が自発的に実行するよう誘導する手法。

**手口:**

| 手口 | 方法 |
|------|------|
| 感染 USB ドライブの放置 | 「給与明細」「プロジェクト計画書」等のラベルを貼った USB を組織内に放置 |
| 偽ダウンロードリンク | 正規ソフトウェア・業務ツールに見せかけたマルウェアを配布 |
| QR コードの改ざん | 公共の場・印刷物の QR コードを悪意ある URL に差し替え |

**観測される出力 → 次のアクション:**

| 出力 | 示唆 | 次のアクション |
|---|---|---|
| マルウェアが実行されてコールバックが届く | ベイティング成功 | C2 接続確立 → バックドア確立 → 技術的な侵入フェーズへ |
| USB が回収される / リンクがクリックされない | 標的の警戒心が高い / 技術的なブロック | 別の手法へ |

**注意（原状回復）:** USB ドライブは対象建物内のみ放置し、回収責任を明示する。感染 USB を外部に持ち出された場合の被害拡大リスクを事前に合意に含める。

## 刺さらなかったとき（全体）

| 状況 | 推定原因 | 代替手段 |
|---|---|---|
| フィッシングページへのアクセスがない | メールが迷惑メールフィルタに捕捉 | 送信元ドメイン・送信インフラを変更 / ベイティングに切り替え |
| 認証情報が取れるが MFA でブロック | 2FA 有効 | Evilginx 等の AITM フィッシング / プリテキスティングで直接アクセス |
| 標的が通報する | セキュリティ意識が高い | 即時中断 / 別の標的 / 別の手法へ |

---

## 注意点・落とし穴

- **技術的な侵入痕跡が少ない**: 正規の認証情報を使用するためログ上は正常なアクセスに見える。UEBA / 異常アクセス検知で初めて発覚するケースが多い
- **成功可否は事前情報の質に依存**: OSINT フェーズを先行させる
- **複合攻撃が基本**: SE 単独で攻撃が完結することは少ない。フィッシングで認証情報取得→技術的手法で権限昇格が主流
- **MFA でもバイパス可能なケースがある**: リアルタイム中間者攻撃（Evilginx 等）

## 本番での前提（必読）

本番でのソーシャルエンジニアリングは**人を対象とする攻撃**であるため、技術調査と異なる法的フレームに服する。

**実施前に書面で取り決めるべき項目:**

- **対象者リスト**: 氏名・所属・役職・メールアドレスを書面で限定（範囲外への波及は契約違反）
- **対象手段**: メール / SMS / 電話 / 物理侵入 / SNS のうちどれを使うか
- **訓練 vs 診断の区分**: 訓練（従業員教育・フィードバックあり）/ 診断（態勢評価・統計報告）で事後対応・人事評価への扱いが変わる
- **実施時間帯**: 業務時間内 / 業務時間外、深夜・休日の電話禁止 等
- **通知範囲**: CISO のみ把握 / IT 部門全員把握 / 全員把握なし のどれか
- **個人情報の取扱**: 取得した認証情報・通話録音・撮影物の保管・破棄ポリシー（個情法対応）
- **物理侵入の事前通知**: 建物管理者・警備会社・地元警察への通知の要否
- **攻撃成功時の即時報告ライン**: 実認証情報取得・端末侵害発生時の連絡先と SLA

**実施時に守ること:**

- 対象者リスト外への波及を必ず防ぐ（家族・取引先のメールアドレスを誤って踏まない）
- 取得した個人情報・通話録音は暗号化保管・テスト完了後即破棄（書面で確認を取る）
- 物理侵入時は身分証・実施合意書のコピーを携行（警察対応用）
- ベイティング（USB 放置）は対象建物内のみ・回収責任を明示
- 「攻撃が止められなくなる」事態（対象者が SOC 通報して内部調査が動く等）の連鎖を想定して中断手順を共有

- **事前合意の要否**: ★★★（書面承認必須）
- **演習環境での扱い**: 制約なし（HTB / OSCP 等は本セクション全項目をスキップしてよい）
